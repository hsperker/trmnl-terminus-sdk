# Minimal v0.1 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> `superpowers:test-driven-development` for production changes and
> `superpowers:verification-before-completion` before every completion claim.
> Keep this plan updated by checking off each completed step.

**Goal:** Finish the smallest useful SDK v0.1: typed playlist assignment for an
existing device, inspectable RFC Problem Details errors, a usable first-run
README, and release evidence against both Terminus 0.71.0 and a physical device.

**Architecture:** Keep the existing synchronous `TerminusClient` and thin
resource-manager design. Add one response model, one strict request model, and
one `DevicesManager`; do not add a service layer or general device mutation
framework. Parse error bodies once into a small value object. Keep live proofs
in guarded scripts and documentation, with all hosts, credentials, and device
identifiers supplied only through the process environment.

**Tech Stack:** Python 3.12+, httpx 0.27+, Pydantic 2, pytest, respx, ruff,
mypy, uv, the official Terminus 0.71.0 container image

**Spec:** `docs/specs/terminus-sdk.md`

## Global constraints

- Support exactly Terminus tag `0.71.0`, resolved commit
  `e0cf90d8ef6d7bc16dfbac8ebab910a9fda9de56`.
- Keep the client synchronous and the resource managers thin.
- Add only device list, lookup, and playlist assignment. Do not add device
  creation, deletion, detachment, or arbitrary patch fields.
- Make production behavior test-first: observe a focused test fail for the
  missing behavior before implementing it.
- Never put a live server URL, email, password, token, API key, device ID, or
  downloaded display image in Git, test output, or documentation.
- Live mutation scripts must stop before network access unless an explicit
  mutation guard equals `1`.
- A physical-device run must restore the prior integer playlist assignment and
  delete its temporary playlist and screen even after failure.
- Do not create or publish a Git tag in this plan. Produce and push a verified
  `0.1.0` release candidate; tagging remains a separate release decision.

### Task 3: Make RFC Problem Details inspectable and secret-safe

**Files:**

- Modify: `src/trmnl_terminus/errors.py`

- Modify: `src/trmnl_terminus/client.py`
- Modify: `src/trmnl_terminus/__init__.py`

**Produces:** `ProblemDetails`, typed `TerminusResponseError.problem`, and
`TerminusValidationError.errors`.

- [ ] **Step 1: Write failing error-contract tests**

Cover a validation response with all five standard members plus extensions:

```python
payload = {
    "type": "https://example.test/problems/invalid",
    "status": 422,
    "title": "Invalid request",
    "detail": "One or more fields are invalid",
    "instance": "/api/devices/23",
    "errors": {"playlist_id": ["is invalid"]},
    "trace_id": "trace-1",
}
```

Assert `problem.extensions` contains only `errors` and `trace_id`, and
`TerminusValidationError.errors` returns the exact `errors` value. Assert a
non-object body leaves `problem is None`. Assert login failure also exposes a
parsed problem. Finally place recognizable password, token, API-key, and
authorization strings in a request/response fixture and assert none appear in
`str(error)` or `repr(error)`.

- [ ] **Step 2: Run the focused test and confirm the red state**

Run `uv run pytest tests/test_errors.py -q`. Expected: import or type assertions
fail because `ProblemDetails` is absent and errors currently retain raw JSON.

- [ ] **Step 3: Implement one defensive parser**

Add a frozen or ordinary small Pydantic value object with the five optional
standard members and `extensions: dict[str, Any]`. Add one internal parser that:

- returns `None` when the response is not JSON or the JSON root is not an object;
- copies valid standard members;
- puts every non-standard key in `extensions`;
- never includes a request body or headers in an exception message.

Use it from native-resource status translation and from login, refresh, and
final-401 authentication failures. Keep the original `httpx.Response`, status,
method, and URL properties. Export `ProblemDetails` and the public exception
types from the package root.

- [ ] **Step 4: Prove the green state and commit**

Run:


### Task 4: Add a guarded physical-device proof runner

**Files:**

- Create: `scripts/run_device_smoke.py`
- Create: `tests/test_device_smoke_script.py`
- Modify: `docs/real-server-smoke.md`

**Produces:** a reversible, typed, user-observed device assignment proof.

- [ ] **Step 1: Add failing safety tests**

Run the script in a subprocess with all `TERMINUS_*` variables removed. Assert
exit code `2`, no stdout, and a stderr line that names only missing variable
names. Repeat with the mutation guard set to `0` and an unreachable
`example.test` URL; the script must stop before network access.

Required environment names are:

```text
TERMINUS_BASE_URL
TERMINUS_EMAIL
TERMINUS_PASSWORD
TERMINUS_DEVICE_ID
TERMINUS_ALLOW_DEVICE_MUTATIONS
```

Test the acknowledgment helper directly: only a trimmed, case-insensitive
`seen` is accepted. Do not build a fake client framework for this script; the
mocked manager tests already own the wire contract, and the live run owns the
workflow proof.

- [ ] **Step 2: Run the focused test and confirm the red state**

Run `uv run pytest tests/test_device_smoke_script.py -q`. Expected: failure
because the runner does not exist.

- [ ] **Step 3: Implement the fail-closed workflow**

After all local guards pass:

1. parse `TERMINUS_DEVICE_ID` as a positive integer;
2. fetch the device with `client.devices.get()`;
3. stop before mutation unless its current `playlist_id` is a positive integer;
4. create a uniquely named empty playlist;
5. create a self-contained high-contrast HTML screen using the device's
   `model_id`, with the literal heading `SDK DEVICE PROOF`;
6. attach the screen to the playlist and read it back;
7. assign the playlist through `client.devices.update()` and read the device
   back to verify the returned assignment;
8. print `Temporary display assigned. Wake the device, then type seen:` and wait
   for stdin for at most ten minutes;
9. treat anything except `seen` as a failed proof;
10. in `finally`, restore the original integer playlist assignment, verify it
    with `devices.get()`, then delete the temporary playlist and screen;
11. fail the run if restoration or cleanup fails.

Print stage names and exception class/status only. Never print configuration,
resource labels, HTML, IDs, URLs, or response bodies.

- [ ] **Step 4: Document the operator contract**

Explain that playlist assignment does not wake a device. The operator must use
the device's normal manual refresh/power-cycle action, visually confirm the
heading, and type `seen`. Explain that an unassigned device cannot be used by
this runner because v0.1 intentionally cannot restore `playlist_id: null`.

- [ ] **Step 5: Prove local safety and commit**

Run:

```sh
uv run pytest tests/test_device_smoke_script.py -q
uv run ruff check scripts tests
uv run mypy src
git diff --check
```

Commit with `test: add reversible physical-device proof`.
